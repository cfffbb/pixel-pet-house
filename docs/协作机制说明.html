1. 角色分工矩阵

🎯 产品经理（PM）— 统筹全局

职责：

  • 需求管理、优先级排序、文档管控
  • 主持所有会议，产出会议纪要
  • 技术评审、协调调度
  • 需求变更评估与流程推进
  • 向老板汇报、申请资源

不直接写代码，但具备审查和决策能力。

🎨 前端专家 — UI 与交互

职责：

  • 所有 UI/HTML/CSS/JS/Vue 组件
  • 审美把关、素材管理（联网搜索）
  • Electron 主进程+渲染进程
  • 打包配置（electron-builder）
  • 兼容性保障（Windows/DPI）

不涉及后端逻辑和数据库。

⚙️ 后端专家 — Java 后端

职责：

  • Java 后端、接口规范、数据库
  • 安全管控（JWT/AES/SQL防注入）
  • 打包部署方案（Maven/JAR）
  • API 文档维护
  • 性能优化

不涉及 UI 和交互。

🧪 测试 — 质量保障

职责：

  • 功能测试、回归测试
  • 缺陷追踪、质量评估
  • 测试用例编写、测试报告产出
  • 接口冒烟测试

独立于开发，不受开发影响。

👑 老板 — 最终决策者

职责：审批需求变更、功能增减、资源调配。拥有最终决策权。不参与日常开发，仅在关键节点审批。

2. 会议制度

2.1 每日站会（15 分钟）

项内容
频率每天 1 次（建议 9:00 或 10:00）
主持PM
参与前端、后端、测试（老板可选）
议程每人 3 分钟：①昨日完成 ②今日计划 ③遇到的阻碍
产出《站会纪要》更新至迭代管理文档待办列表

2.2 阶段评审会

项内容
触发每个产出节点结束后（SRS 定稿 / 接口规范完成 / UI 优化完成 / 打包完成 / 测试完成）
主持PM
参与全员 + 老板
议程①审查该阶段文档/代码/测试报告 ②确认是否达标 ③决定是否进入下一阶段
产出《阶段评审纪要》+ 评审结论（通过/有条件通过/不通过）
不通过处理记录缺陷→指派修复→重新评审（不跳阶段）

2.3 紧急会议

项内容
触发条件①测试发现致命/严重缺陷 ②重大需求变更 ③技术方案无法落地
主持PM（立即召集）
参与相关角色 + 老板
议程①问题描述 ②影响评估 ③决策方案 ④分工执行
产出《紧急会议纪要》+ 决策记录 + 紧急待办
时效要求触发后 30 分钟内召开，2 小时内出决策

2.4 周度复盘会

项内容
频率每周最后一天（建议周五 16:00）
主持PM
参与全员 + 老板
议程①本周进度回顾 ②质量指标 ③风险更新 ④下周计划调整
产出《周报》+ 更新迭代管理文档版本记录

3. 沟通通道

场景通道时效
日常沟通项目群聊（飞书/微信）即时
文档协作共享文档（飞书文档/腾讯文档）实时同步

紧急问题电话/即时通讯 → 紧急会议30 分钟内响应
老板汇报阶段评审会 + 周报按节点

4. 跨模块问题处理（越界管控）

原则：任何角色发现其他模块问题，不可越界修改，须提交 PM 统一调度。

  1. 发现者提交《问题报告》给 PM（描述问题+影响+建议）
  2. PM 评估后指派对应负责人处理
  3. 负责人处理后反馈 PM 确认
  4. PM 更新迭代管理文档待办状态

示例：测试发现前端显示的数据格式不对 → 不直接找后端改 → 提交 PM → PM 判断是后端返回格式问题 → 指派后端修复。
